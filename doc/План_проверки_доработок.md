# План проверки доработок (Windows)

Проверяемые пункты: H-1, H-2, H-3, H-5, M-2, M-3, M-9, M-10, M-11. Установщик (M-1/M-8) и JP2 в этот план не входят: см. `doc/План_установщика.md`. H-4 отложен.

## 1. Подготовка

1. Распаковать архив в отдельную папку (например, `C:\AVIFTest\app`). Не запускать на рабочей копии с личными фото.
2. Установлены и доступны в PATH: `pwsh` (PowerShell 7), `ffmpeg`, `avifenc`, `gif2webp`. Проверка: `ffmpeg -version`, `avifenc --version`, `gif2webp -version`.
3. Скопировать `Settings.psd1` в `Settings.psd1.orig`. Перед каждым блоком восстанавливать его. Сохранить значения `DeleteOriginals`, `AnalysisThreads`, `TimeoutSec`, `TimeoutSecSingleFile`.
4. Тестовые папки создавать внутри `C:\AVIFTest\cases\`. Каждый кейс — своя папка, пересоздаваемая с нуля: `C:\AVIFTest\cases\H2-01\`, и т.д.
5. Логи: папка логов из `Get-LogDir` (см. `bin/Logging.ps1`). Перед кейсом очищать или запоминать время запуска.
6. Для каждого кейса сохранить: скриншот сводки плана, содержимое `warnings.log` и `corrupt.log` (если созданы), список файлов папки до и после (`dir /b`).

## 2. Примеры файлов

Все файлы кладутся в папки кейсов. Команды для Windows (PowerShell, с установленным ffmpeg).

| ID | Файл | Нужен для | Как получить |
|---|---|---|---|
| S1 | `photo.jpg` (2000×1500) | H-1, H-2, H-5, M-2 | `ffmpeg -f lavfi -i testsrc2=size=2000x1500 -frames:v 1 photo.jpg` |
| S2 | `IMG.jpg`, `IMG.png`, `IMG.bmp` (одинаковое базовое имя) | H-2 | `ffmpeg -f lavfi -i testsrc2=size=1600x1200 -frames:v 1 IMG.jpg` (то же для `.png`, `.bmp`) |
| S3 | `photo.jpg`, `photo.png`, `photo_2.jpg` | H-2 (пример с `photo_2`) | `photo.png` — как S2; `photo_2.jpg` — как S1 |
| S4 | `alpha.png` (полупрозрачные пиксели) | регрессия H-1/H-2 | `ffmpeg -f lavfi -i color=c=red@0.5:s=800x600 -frames:v 1 -pix_fmt rgba alpha.png` |
| S5 | `anim.gif` (анимированный) | регрессия H-2 (расширение `.webp`) | `ffmpeg -f lavfi -i testsrc2=size=480x360:rate=10 -t 2 anim.gif` |
| S6 | `static.gif` | регрессия | `ffmpeg -f lavfi -i testsrc2=size=480x360 -frames:v 1 static.gif` |
| S7 | `truncated.jpg` — обрезанный `photo.jpg` (первые 3000 байт) | H-3 `Corrupt` | PowerShell: `[IO.File]::WriteAllBytes("$PWD\truncated.jpg", [IO.File]::ReadAllBytes("$PWD\photo.jpg")[0..2999])` |
| S8 | `garbage.jpg` — 10 КБ случайных байт | H-3 `Corrupt` (или `Unreadable`, записать фактический результат) | PowerShell: `$b=New-Object byte[] 10240; (New-Object Random).NextBytes($b); [IO.File]::WriteAllBytes("$PWD\garbage.jpg",$b)` |
| S9 | `locked.jpg` | H-3 `Unreadable` (блокировка) | Любой JPG. Держать открытым в другом процессе: PowerShell-окно `$fs=[IO.File]::Open("$PWD\locked.jpg",'Open','Read','None'); Read-Host` (не закрывать до конца кейса) |
| S10 | Файл OneDrive «Только в сети» (Files On-Demand) | H-3 `Unreadable` (cloud) | Нужен файл из вашей OneDrive, отмеченный как «Только в сети». Пример — см. раздел 3 |
| S11 | `big.png` (8000×6000) | M-2, M-3 (долгое кодирование) | `ffmpeg -f lavfi -i testsrc2=size=8000x6000 -frames:v 1 big.png` |
| S12 | `tiny.jpg` (≈1 КБ) | регрессия (`TooSmall`) | `ffmpeg -f lavfi -i testsrc2=size=32x32 -frames:v 1 tiny.jpg` |
| S13 | `empty.jpg` (0 байт) | регрессия (`ZeroBytes`) | `New-Item empty.jpg -ItemType File` |
| S14 | `compress_analysis.clixml` от другой папки | H-5 (устаревший файл) | Выполнить анализ папки `C:\AVIFTest\cases\H5-other\`, найти `%TEMP%\compress_analysis.clixml` сразу после анализа и скопировать в `C:\AVIFTest\stale\` |

Дополнительно от вас:
- **Фото из вашей коллекции**: 3–5 JPG с камеры и 1–2 PNG (скриншоты). Нужны для проверки на реальных данных. Не обязательно большие.
- **Файл OneDrive «Только в сети»** (S10). Если облака нет — пропустить только этот подпункт.
- **Сетевой диск** (`\\server\share`, подключённый как буква) и **флешка** (FAT32 или exFAT) — для M-9.
- Диск, где у вас **отключена корзина** (свойства диска → «Не перемещать файлы в корзину»), либо разрешение на её отключение в тестовом разделе.

## 3. Кейсы

Ожидаемый результат — в последнем столбце. Если результат не совпадает, зафиксировать фактический вывод и `warnings.log`.

### H-1. Явная передача DeleteOriginals

| № | Режим | Settings `DeleteOriginals` | Файлы | Ожидание |
|---|---|---|---|---|
| H1-1 | Custom → «No» | 1 | S1 | Сводка: `Delete src: No`. Оригинал на месте. |
| H1-2 | Custom → «Yes» | 0 | S1 | Сводка: `Delete src: Yes (Recycle Bin)`. Оригинал в корзине. |
| H1-3 | Quick (Enter) | 1 | S1 | Оригинал в корзине. |
| H1-4 | Quick (Enter) | 0 | S1 | Оригинал на месте. |
| H1-5 | Одиночный файл (перетащить файл на `.bat`) | 1 | S1 | Оригинал в корзине. |

Проверить, что `Settings.psd1` не изменился во всех кейсах H-1, кроме M-10 (см. ниже).

### H-2. Имена выходных файлов и манифест (режим без удаления)

| № | Шаги | Ожидание |
|---|---|---|
| H2-1 | Папка `H2-01`: S2 (`IMG.jpg`, `IMG.png`, `IMG.bmp`). Custom → «No». | Созданы `IMG.avif`, `IMG_1.avif`, `IMG_2.avif`. Все три исходника на месте. Нет `.ACtmp`. В `.avifcompress_done.txt` три строки (+ строка-комментарий). |
| H2-2 | Повторный запуск на той же папке (как H2-1) | Все три исходника пропущены как `OutputExists`. Новых файлов нет. Манифест не меняется. |
| H2-3 | Изменить `IMG.jpg` (например, пересохранить с другим качеством) и запустить снова | Обработан только `IMG.jpg`. Результат: `IMG_3.avif`. В манифесте новая строка. |
| H2-4 | Папка `H2-04`: `photo.jpg` и чужой `photo.avif` (созданный вами вручную, не в манифесте). Custom → «No». | Результат `photo_1.avif`. Чужой `photo.avif` не перезаписан. |
| H2-5 | Папка `H2-05`: S3 (`photo.jpg`, `photo.png`, `photo_2.jpg`). Custom → «No». | Имена без дублей: `photo.avif`, `photo_1.avif`, `photo_2.avif` (для разных исходников). Ни один файл не перезаписан. |
| H2-6 | Папка `H2-06`: S3. Custom → «Yes» (удаление). | Без манифеста. Имена с суффиксами, как в H2-5; исходники в корзине. Манифест не создан. |
| H2-7 | Вложенные папки: исходники в `sub\`. Custom → «No». | Манифест создаётся в `sub\`, а не в корне. |
| H2-8 | Сценарий 1 (подтверждён пользователем): папка с `1.jpg`, режим «No». Первый проход → `1.avif`. Добавить `1.png` и запустить снова. | `1.jpg` пропущен по манифесту (`OutputExists`). `1.png` → `1_1.avif`. Манифест содержит строки для `1.jpg` и `1.png`. |
| H2-9 | Сценарий 2 (подтверждён пользователем): папка с `1.jpg`, `1.png` и уже существующим `1.avif` (не в манифесте), режим «No», первый запуск | Порядок по полному пути: `1.jpg` → `1_1.avif`, `1.png` → `1_2.avif`. Существующий `1.avif` не изменён. Манифест содержит строки для двух исходников. |

### H-3. Классификация «повреждён» / «не удалось прочитать»

| № | Файл | Ожидание |
|---|---|---|
| H3-1 | S7 `truncated.jpg` | Фактический результат записать. Ожидается `Corrupt`: файл в `_corrupt\`, строка в `corrupt.log`. Если ffmpeg декодирует частично (`Decodable`), записать в отчёт, это не ошибка программы. |
| H3-2 | S8 `garbage.jpg` | Фактический результат записать. Если `Corrupt` — в `_corrupt\`. Если `Unreadable` — файл на месте, строка в `warnings.log` с причиной `Unreadable: ...`. |
| H3-3 | S9 `locked.jpg` (держится открытым) | `Unreadable: file is locked or cannot be opened`. Файл на месте. Не в `_corrupt\`. |
| H3-4 | S10 облачный файл «Только в сети» | `Unreadable: cloud file is not downloaded (offline)`. Не скачивается, не перемещается. |
| H3-5 | Счётчик | В сводке строка `Unreadable: N (not moved, → warnings.log)`. |
| H3-6 | Переименовать `ffmpeg.exe` временно, запустить на папке с подозрительным файлом | Анализ останавливается до декодирования с сообщением `ffmpeg was not found in PATH`. Вернуть `ffmpeg.exe`. |

### M-9. Корзина на диске источника

| № | Диск | Ожидание |
|---|---|---|
| M9-1 | Локальный NTFS, корзина включена | Строка `Note:` не выводится, `Delete src: Yes (Recycle Bin)` при Settings = 1. |
| M9-2 | Локальный NTFS, корзина отключена для диска | `Note: Originals kept for this run: Recycle Bin is turned off ...`. Оригиналы на месте. `Settings.psd1` без изменений. Строка в `warnings.log`. |
| M9-3 | Сетевой диск | `Note: drive ... is Network, no Recycle Bin`. Оригиналы на месте. |
| M9-4 | Флешка | `Note: drive ... is Removable, no Recycle Bin`. Оригиналы на месте. |
| M9-5 | Диагностика реестра | Подтверждено на тестовой машине: `NukeOnDelete` существует на всех дисках, значение `0` (корзина включена). Для M9-2 ожидается значение `1` в ключе тома или глобальном ключе. Вывести `reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket" /s` до и после отключения корзины и приложить вывод. |

### M-10. Некорректный AnalysisThreads

| № | Значение в `Settings.psd1` | Ожидание |
|---|---|---|
| M10-1 | `AnalysisThreads = 999` | Предупреждение `AnalysisThreads changed: 999 -> <число ядер> (reason: more than logical processors (...))`. Файл `Settings.psd1` содержит число ядер. Строка в `warnings.log`. |
| M10-2 | Тот же файл, второй запуск | Предупреждения нет (значение уже корректно). |
| M10-3 | `AnalysisThreads = -5` | `-> 0 (reason: negative value)`. Файл исправлен на `0`. |
| M10-4 | `AnalysisThreads = 4` (валидно) | Без предупреждения, файл не меняется. |

## 4. Регрессия

- Обычный прогон на смешанной папке S1–S6, S12, S13: без ошибок, результаты открываются.
- Проверка размеров: результат меньше исходника; если нет — `Skip` (как раньше).
- Логи создаются, `warnings.log` и `corrupt.log` появляются только при событиях.

## 5. Что вернуть

1. Архив логов (`logs\`), `warnings.log`, `corrupt.log`.
2. Скриншоты сводки для H1-1, H2-1, H2-3, H3-3, M9-2, M10-1.
3. Таблица фактических результатов по всем №. Ответы в виде `№ — OK / FAIL — что увидели`.
4. Вывод `reg query` (M9-5).
5. Версии `ffmpeg`, `avifenc`, `gif2webp`, `pwsh`, Windows.

## 6. Не проверяется в этом цикле

- H-4 (альфа в fallback) — отложено.
- JP2 (бинарный парсер) — не реализован. Потребуются два варианта JP2-файлов.
- Установщик (M-1/M-8) — см. `doc/План_установщика.md`.
- M-3 в части фонового fallback — не реализован.
