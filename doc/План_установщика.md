## Исходный раздел M-1 и M-8

### M-1 и M-8. Единый установщик компонентов

**Что уже согласовано:** один скрипт с флагом компонента, хранение версии, даты релиза и общей даты последней проверки; проверка через страницу релиза вместо `api.github.com`; переименование папок установки в `tools\ACffmpeg`, `tools\ACavifenc`, `tools\ACgif2webp` (по аналогии с `.ACtmp`), чтобы однозначно искать старые записи PATH.

**Что, по моей оценке, не учтено (нужно решить):**

1. **Получение «последней версии» без API.** Варианты: `https://github.com/<repo>/releases/latest` возвращает `302` с тегом в `Location` (без API); `…/releases.atom` содержит теги и даты обновления. Для gyan.dev и Google Storage разбор страницы остаётся, и формат нужно проверить. Дата релиза может отсутствовать: тогда сравнение только по версии, а дата для отображения.
2. **Определение установленной версии.** `ffmpeg -version`, `avifenc --version`, `gif2webp -version`: формат вывода нужно проверить для каждого бинарника. Версию ffmpeg из сборки gyan.dev нужно парсить аккуратно.
3. **Где хранится состояние.** `installers/state.psd1` в git (M-11). Нужна отдельная игнорируемая запись состояния. Поле `LastUpdateCheck` общее, `Installed` и `ReleaseDate` на компонент. Текущий `Set-Psd1Value` (регулярное выражение) для вложенных структур не подходит: нужна полная перезапись файла.
4. **Политика проверки обновлений.** Не блокировать запуск: короткий таймаут (3–5 с), отказ сети не приводит к ошибке, интервал проверки (например, 24 ч), вариант «пропустить эту версию».
5. **Атомарное обновление.** Загрузка во временную папку → проверка (хеш, если источник его публикует; иначе размер и успешная распаковка) → распаковка в staging → переименование старой папки → перемещение новой → удаление старой только после успешного запуска `<tool> -version`. Откат при ошибке.
6. **Миграция.** Существующие установки `tools\ffmpeg` и т.п. нужно переименовать (или переустановить) и **удалить их записи из PATH** до переименования. Иначе `Get-Command` будет находить старые пути.
7. **Записи PATH.** Если PATH остаётся пользовательским, поиск по префиксу `tools\AC*` однозначен. Альтернатива: вообще не менять пользовательский PATH, а добавлять папки в `$env:Path` процесса в `Main.ps1`. Это устраняет побочные эффекты, но не даёт использовать инструменты вне программы. **Нужно решение.**
8. **Права.** Установка в папку проекта не требует прав администратора. Установка pwsh через MSI требует UAC. Вынести её из единого скрипта или оставить отдельно?
9. **Контрольные суммы.** Проверить, публикуют ли источники хеши (gyan.dev, libavif, libwebp). Если нет, проверка только по размеру и распаковке, и это нужно явно указать пользователю.
10. **Фиксация версий.** Обновляться до «latest» или фиксировать проверенную версию в конфиге? Предлагаю фиксацию по умолчанию с возможностью обновления.
11. **Тесты.** Установка с нуля; обновление со старой версии; офлайн; повреждённый архив; прерванное обновление (откат); миграция PATH.

## Решения раунда 2 (установщик)

### Единый установщик компонентов
Принято:
- Версия сравнивается, дата справочная.
- Установленная версия: `ffmpeg -version` → `^ffmpeg version (\S+)`; `avifenc --version` → `Version: (\S+)`; `gif2webp -version` → `WebP Encoder version: (\S+)`. Для сравнения берётся ведущая числовая часть.
- Последняя версия avifenc: `https://github.com/AOMediaCodec/libavif/releases/latest` возвращает `302` с тегом в `Location` (проверено: тег `v1.4.2`, совпадает с установленной версией). Дата — из `releases.atom` (поле `updated`).
- Миграция не делается. Пункт 7 (PATH): записи делаем, поиск старых — по префиксу `tools\AC*`.
- Фиксация версий не делается.
- pwsh: только ссылка на страницу, сообщение о перезапуске консоли и пауза перед выходом.

Не проверено (песочница не имеет доступа): страницы gyan.dev и Google Storage. Парсинг последней версии ffmpeg и libwebp нужно проверить на тестовой машине.

## Решения раунда 3 (установщик)

### Установщик компонентов

Подтверждено:
- Версия сравнивается, дата справочная.
- Хешей в релизах нет. Для avifenc в релизе v1.4.2 опубликованы только архивы (`windows-artifacts.zip`, `linux-artifacts.zip`, `macOS-artifacts.zip`). Проверка загрузки — размер и успешный запуск `<tool> -version` после распаковки.
- Миграция не делается, PATH: записи делаем, поиск старых — по префиксу `tools\AC*`.
- Интервал проверки — опция в `Settings.psd1`: `UpdateCheckInterval = 'Daily' | 'Weekly' | 'Monthly' | 'Off'` (сутки, неделя, месяц, отключено). Дата последней проверки общая, хранится в файле состояния (`installers/state.psd1`, игнорируется git).
- pwsh: ссылка на страницу, сообщение о перезапуске консоли, пауза.

Используемые ссылки (для проверки):
- **ffmpeg** (gyan.dev, данные пользователя; текущая версия 9.0.2, последняя сборка 2026-10-12):
  - версия: `https://www.gyan.dev/ffmpeg/builds/release-version` → `9.0.2`;
  - дата: `https://www.gyan.dev/ffmpeg/builds/last-build-update` → `2026-10-12`;
  - архив 7z: `https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.7z`, SHA-256 (`…7z.sha256`): `4705843ccaaf54257c16ad90f3e952ece33c17df964ecf7bfdbb0f49c7171077`;
  - архив zip: `https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip`, SHA-256 (`…zip.sha256`): `60f467265b1e312373dbcd92200c2618a74850f98d3d078e94296bb3fa2047ba`.
  - Installer берёт хеш из `.sha256`-файла; значения выше — для тестов. Текущий скрипт сначала пробует .7z, потом .zip.
- **avifenc** (libavif): `https://api.github.com/repos/AOMediaCodec/libavif/releases/latest` — будет заменён на `https://github.com/AOMediaCodec/libavif/releases/latest` (302 на тег), список релизов: `https://github.com/AOMediaCodec/libavif/releases.atom`. Архив: `https://github.com/AOMediaCodec/libavif/releases/download/<тег>/windows-artifacts.zip`.
- **gif2webp** (libwebp, данные пользователя): последний релиз `1.6.0` (2025-07-09T22:55:36Z), файл `libwebp-1.6.0-windows-x64.zip`. Одинаково в `https://github.com/webmproject/libwebp/releases.atom` и `https://storage.googleapis.com/downloads.webmproject.org/releases/webp/index.html`. Installer может брать версию из atom-ленты (проверка даты), архив — из storage.googleapis.com.

Ограничение: из песочницы gyan.dev и storage.googleapis недоступны; данные выше получены пользователем, проверку формата разбора делаем на тестовой машине.
