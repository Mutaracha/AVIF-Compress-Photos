## 2. Высокий приоритет (H)

### H-1. Выбор «No, keep originals» не работает — оригиналы всё равно уходят в корзину [код]

- `bin/Main.ps1:795` — при выборе «[1] No» переменная `$DelFlag` становится пустой строкой.
- `bin/Main.ps1:809` — пустой флаг не передаётся в `AnalyzeFiles.ps1`.
- `bin/AnalyzeFiles.ps1:49-50` — параметр `-DeleteOriginal` проверяется через `PSBoundParameters.ContainsKey(...)`. Если флага нет, используется значение из `Settings.psd1`.
- `Settings.psd1:14` — `DeleteOriginals = 1` (по умолчанию).

Итог: пользователь явно отказался от удаления, но после успешного кодирования исходники отправляются в корзину. Нарушен сценарий `tests.txt` 5.4.2.

**Исправление:** всегда передавать явное значение, например `-DeleteOriginal:([bool]$dc -eq 0)` или отдельный ключ `-KeepOriginal`.

### H-2. Коллизия имён выходных файлов при параллельной обработке → потеря результата [код]

Пример: в папке есть `IMG_001.jpg` и `IMG_001.png` (или `.jpg` + `.jpeg`, `.bmp` + `.tif`).

- `bin/AnalyzeFiles.ps1` и `Get-UniqueOutputPath` (`bin/FileOps.ps1:159`) проверяют только **уже существующие** файлы.
- Имя выходного файла вычисляется в `bin/CompressPhotos.ps1:336` (`Start-NextTask`) в момент запуска задачи. Имя нигде не резервируется.
- Пока первая задача пишет `IMG_001.avif.ACtmp`, `Get-UniqueOutputPath` для второй задачи снова возвращает `IMG_001.avif`, потому что файла ещё нет.
- Обе задачи пишут в один и тот же `IMG_001.avif.ACtmp`. Затем `Rename-TempToFinal` (`FileOps.ps1:145`) **молча перезаписывает** готовый `.avif` (`File.Delete` перед `Move`).
- Оба исходника затем уходят в корзину (`DeleteOriginals = 1`), а в результате остаётся один `.avif`, и он может быть повреждён из-за одновременной записи.

Условие: `EncodingParallel ≥ 2`. По формуле `Config.ps1` (`floor(cores/4)`, минимум 1) это 8+ логических ядер и достаточно памяти. Для одинаковых базовых имён задачи обычно попадают в одну фазу, поэтому дубли запускаются одновременно.

**Исправление:** резервировать выходные имена при построении плана (`BuildEncodingPlan.ps1`) или вести общий словарь занятых путей в `CompressPhotos.ps1`. Также запретить молчаливую перезапись в `Rename-TempToFinal`.

### H-3. Ошибки чтения/запуска ffmpeg классифицируются как «повреждённый файл» → файлы перемещаются в `_corrupt` [код]

- `bin/ImageProbe.ps1:489` и `:509` — `Test-CanDecode` (строки 466-511): любое исключение (ffmpeg не запустился, файл занят другим процессом, OneDrive не успел скачать файл, нет прав) даёт `$canDecode = $false`.
- Такой файл попадает в `Corrupt`, и `AnalyzeFiles.ps1` вызывает `Move-ToCorruptFolder` (строка 300).
- Файлы, которые просто не удалось прочитать в момент анализа, перемещаются из рабочей папки без подтверждения.

**Исправление:** различать «декодер сообщил об ошибке формата» (`corrupt`) и «не удалось запустить/прочитать» (`unreadable` → пропуск с предупреждением, без перемещения). Не перемещать файлы при ошибках ввода-вывода.

### H-4. Fallback для PNG с прозрачностью теряет альфа-канал [код]

- `bin/ImageEncoding.ps1:94` — для `AvifDirect` fallback-шаг ffmpeg жёстко использует `-pix_fmt yuv444p`.
- `Invoke-AvifFallback` при `HasAlpha` сохраняет промежуточный файл как `.png`, но ffmpeg с `yuv444p` уже не сохраняет альфу.
- Результат: при срабатывании fallback для PNG с прозрачностью получается непрозрачный AVIF, прозрачные пиксели становятся цветными (часто чёрными). Ошибки нет, успех фиксируется, и файл проходит проверку размера.
- `tests.txt` 6.4.1 покрывает fallback только для JPG, поэтому этот случай не тестируется.

**Исправление:** для альфа-случая использовать `-pix_fmt rgba`/`yuva444p` или вообще не переключаться на `yuv444p`. Учитывать `StaticPixFmt` и добавить тест.

### H-5. Устаревшие временные файлы могут запустить обработку чужой папки [код]

- `bin/Main.ps1:546` и `:832` — после анализа Main проверяет только **наличие** `compress_analysis.clixml`, но не код выхода самого шага и не свежесть файла.
- В `AnalyzeFiles.ps1` при выходах с кодом 0 без кандидатов («Nothing found», «No supported files», «No files after pre-filter») новый файл **не записывается**.
- Если предыдущий сеанс был прерван между анализом и построением плана, старый `compress_analysis.clixml` останется в `%TEMP%`. Следующий запуск с пустой папкой пройдёт проверку и закодирует файлы из старого списка (`Test-TaskReady` проверяет только существование и `LastWriteTime`).
- Аналогично для `compress_plan.clixml` (`Main.ps1:559`, `:845`): `BuildEncodingPlan` выходит с кодом 0 без записи плана при «No candidates».

**Исправление:** перед каждым этапом удалять старый временный файл; передавать путь/токен сеанса; проверять, что файл создан именно в этом запуске (время или GUID в имени).

## 3. Средний приоритет (M)

### M-1. Установщик, завершившийся ошибкой, сообщает об успехе [код]

- `bin/Config.ps1:424` — `& $InstallerScript` вызывается без проверки результата. Установщики при ошибке вызывают `exit 1`, а `exit` внутри скрипта не выбрасывает исключение, поэтому `catch` не срабатывает.
- Далее (строки ~433-445): если команда не найдена, выставляется `Set-StateFlag = 1`, выводится «installed successfully!» и выполняется `exit 0`.
- `tests.txt` 2.3.4 ожидает сообщение об ошибке и `exit 1`. Фактически пользователь видит ложный успех.

**Исправление:** проверять `$LASTEXITCODE` после вызова установщика и не выставлять флаг, если команда не найдена.

### M-2. Аварийное завершение и Ctrl+C оставляют осиротевшие процессы и `.ACtmp` [код]

- `CompressPhotos.ps1` (trap, строка 23) при сбое вызывает только `Remove-StderrPool`. Дочерние `ffmpeg`/`avifenc`/`gif2webp` не завершаются.
- Обработчика `CancelKeyPress` нет (grep по `bin/` ничего не нашёл). Ctrl+C, закрытие окна и `kill` не запускают очистку, а `Remove-TempFiles` выполняется только при нормальном завершении.
- `tests.txt` 10.6 («Stderr pool очищается через trap» при Ctrl+C или kill) не выполняется.

**Исправление:** реестр запущенных процессов и очистка через `finally` + `[Console]::CancelKeyPress`; при старте очищать `*.ACtmp` и осиротевшие процессы.

### M-3. Fallback выполняется синхронно и блокирует пул [код]

- `Finalize-EncodingJob` → `Invoke-AvifFallback` → `Invoke-DirectCommand` (`ImageEncoding.ps1:245/260/302/314`, `Process.ps1`) вызывается из основного цикла `Process-TaskQueue`.
- Пока fallback работает (до двух шагов по `TimeoutSec`), остальные задачи не опрашиваются: их таймауты не проверяются, прогресс не обновляется, клавиша Q не читается.
- При `TimeoutSec = 0` (это допустимое значение в `Test-ProjectSettings`) fallback не ограничен по времени и может зависнуть навсегда.

**Исправление:** выполнять fallback как обычную фоновую задачу с таймаутом, либо хотя бы применять минимальный таймаут при `TimeoutSec = 0`.

### M-4. Ошибки ffmpeg в pipe-режиме не захватываются [код]

- `Start-ShellJob` (`Process.ps1:102`): `… | avifenc … 2>"slot"`. Редирект `2>` относится только к `avifenc`, поэтому stderr ffmpeg уходит в скрытую консоль и теряется.
- Код выхода `cmd` — это код последней команды (`avifenc`). Если ffmpeg упал, а avifenc завершился кодом 0 на усечённом потоке, проверяется только размер файла (`MinBytes = 100`).
- Диагностика в логах (`[FAILED]`, `Reason`) для ffmpeg-ошибок пустая.

**Исправление:** писать stderr каждого этапа отдельно (например, через `2>` внутри `ffmpeg` и перенаправление в файл) и учитывать `PIPESTATUS`-подобную проверку.

### M-5. Неполная валидация `Settings.psd1` [код]

`Test-ProjectSettings` (`Config.ps1`) не проверяет значения, которые напрямую передаются в avifenc/ffmpeg:

- `Avifenc.AlphaPng.Rate`, `AlphaGif.Rate` (`limited`/`full`, `l`/`f`);
- `Tune` (`psnr`/`ssim`/`iq`);
- `AlphaGif.Y` (420/422/444);
- `AqMode` (0-3), `AutoTiling`, `EnableChromaDeltaQ`, `SpeedDelta`;
- `General.TimeoutSecSingleFile` (отрицательное значение молча отключает таймаут).

Неверное значение приведёт к тому, что каждая задача упадёт с ошибкой, и пользователь увидит сотни `[FAILED]` вместо понятного сообщения о конфигурации.

### M-6. Некорректный ввод в меню вызывает аварийное завершение [код]

`UI.ps1`, функция `Read-ValidatedNumber`: проверка `'^\d+$'` пропускает длинные строки, например `99999999999`, а затем `[int]$raw` выбрасывает исключение переполнения. Это не перехвачено и уходит в trap, exit 99.

**Исправление:** использовать `[int]::TryParse` или `[long]` с проверкой диапазона.

### M-7. Удаление в корзину: ошибки скрыты, поведение на внешних дисках [код / проверить на Windows]

- `FileOps.ps1:46` `Remove-ToRecycleBin` при ненулевом коде SHFileOperation только пишет `Write-Warning`. Файл-оригинал остаётся, но успешная конвертация уже засчитана (`Register-Success` увеличивает счётчики до удаления).
- Пути длиннее 260 символов (`tests.txt` 11.3) и файлы только для чтения (11.2) — типичные случаи ошибки. Ожидание «корректная обработка» не подкреплено кодом.
- [проверить на Windows] Для сетевых дисков и съёмных носителей корзины обычно нет: при `FOF_NOCONFIRMATION` файлы удаляются безвозвратно. Пользователь может не знать об этом.

### M-8. Установщики: нет проверки целостности и побочные эффекты PATH [код]

- Ни один из установщиков (`avifenc`, `ffmpeg`, `gif2webp`) не проверяет контрольные суммы или подписи загруженных архивов (gyan.dev, GitHub, storage.googleapis.com).
- `installers/avifenc-Install.ps1:316` (`Add-DirectoryToUserPath`) удаляет из пользовательского PATH **все** записи, у которых последний сегмент совпадает с именем папки установки (`libavif`, `ffmpeg`, `gif2webp`). Например, `C:\ffmpeg` (очень распространённый путь ручной установки) будет удалён.
- Запросы к `api.github.com` без токена ограничены лимитом анонимных запросов.

### M-9. Quick start: оригиналы удаляются через 3 секунды без подтверждения [код]

- `Main.ps1`: через 3 с без нажатия выбирается Quick start, а `DeleteOriginals = 1` по умолчанию. В пользовательском режиме Enter тоже означает «Yes, delete».
- Если пользователь отвлёкся, исходники уходят в корзину. Для сетевых дисков см. M-7.

**Исправление:** по умолчанию не удалять оригиналы (`DeleteOriginals = 0`) либо увеличить таймаут/требовать явного подтверждения при удалении.

### M-10. Побочный эффект на чтение: `Settings.psd1` перезаписывается [код]

`Get-ParallelismSettings` (`Config.ps1`) вызывается из четырёх скриптов. Если `AnalysisThreads` больше числа ядер, функция **переписывает** `Settings.psd1` через `Set-Psd1Value`. Пользователь не получает уведомления, а файл меняется при обычном запуске.

### M-11. `gitignore.txt` не работает как `.gitignore` [код]

Файл назван `gitignore.txt`, поэтому Git его не применяет (`git check-ignore` ничего не нашёл). В индексе оказываются:

- `installers/state.psd1` — runtime-состояние, меняется при каждом запуске;
- при первом запуске появятся `logs/` и `tools/` (бинарники ffmpeg/avifenc, сотни мегабайт), которые легко закоммитить случайно.

**Исправление:** переименовать в `.gitignore` и убрать `installers/state.psd1` из индекса (`git rm --cached`).

## 4. Низкий приоритет (L)

- **L-1.** `CompressPhotos.ps1:336-340` (`Start-NextTask`): задача извлекается из очереди до проверки наличия свободного слота. Если слота нет, задача теряется без записи в лог. Теоретически, т.к. число слотов равно `Parallel`.
- **L-2.** `$running[$job.SourcePath]` (`CompressPhotos.ps1`): ключ по пути источника. Дубликат пути в плане перезапишет запись и осиротит процесс.
- **L-3.** `Logging.ps1:166`: `Write-FailedEntry` использует `$Task.FileKind`, которого нет в задаче. Поле `Kind:` в логах всегда пустое.
- **L-4.** `AnalyzeFiles.ps1:182`: для статических GIF при проверке существующего файла используется расширение `.webp`, хотя выход статического GIF — `.avif`. Файл `photo.webp` может ошибочно пропустить `photo.gif`, а существующий `photo.avif` не учитывается (получается `photo_1.avif`).
- **L-5.** `ImageProbe.ps1:92`: для PNG с палитрой прозрачность ищется только в первых 4 строках. Прозрачность в нижней части изображения не будет обнаружена.
- **L-6.** `Process.ps1:102`: путь вставляется в командную строку `cmd /d /c`. Внутри кавычек `&`, `|`, `^` безопасны, но `%` может быть раскрыт как переменная окружения (имена файлов вида `100%.jpg`). [проверить на Windows]
- **L-7.** `FileOps.ps1` `Move-ToCorruptFolder`: если копирование прошло, а удаление исходника не удалось, функция возвращает `$null`, и дубликат остаётся без записи в лог.
- **L-8.** `UI.ps1`: в файле есть закомментированные (`<# … #>`) дубли `Show-Progress` и `Write-FinalSummary`. Это мёртвый код, но путает при чтении.
- **L-9.** `BuildEncodingPlan.ps1`: при нулевом числе задач скрипт выходит с кодом 0, а `Main.ps1` продолжает работу через `CompressPhotos`, который завершается с кодом 1, вместо возврата к выбору папки.

## 5. Что проверить на Windows (приоритет)

1. H-2: папка с `IMG.jpg` + `IMG.png` (+ `IMG.bmp`, `IMG.tif`) при `AvifencJobsPerTask`/`EncodingParallel ≥ 2`. Ожидается дубликат/перезапись.
2. H-1: пользовательский режим, «No, keep originals» при `DeleteOriginals = 1` в `Settings.psd1`. Ожидается, что исходники уйдут в корзину.
3. H-4: PNG с прозрачностью, принудительный fallback (например, повреждённый `avifenc`-вызов или переименованный кодировщик). Проверить альфу в результате.
4. H-3: файл, открытый другой программой с эксклюзивной блокировкой, и файл в OneDrive «только онлайн». Проверить, не попадает ли он в `_corrupt`.
5. M-1: отключить сеть и запустить установку ffmpeg. Ожидается `exit 1` и сообщение об ошибке.
6. M-6: ввод `99999999999` в пользовательском меню качества.
7. M-5: `Rate = "x"` или `Tune = "foo"` в `Settings.psd1`.
8. M-2: Ctrl+C во время кодирования. Проверить, остались ли `avifenc.exe` и `*.ACtmp`.
9. Удаление оригиналов на сетевом диске или флешке (M-7).

## 6. Рекомендуемый порядок исправлений

1. H-1 и H-2 (потеря данных / неверный результат).
2. H-3 и H-5 (ложное перемещение и обработка чужих файлов).
3. H-4 (качество при fallback).
4. M-2, M-3 (надёжность при сбоях и таймаутах).
5. M-5, M-6, M-1 (валидация и корректные сообщения).
6. M-11 (Git-гигиена) и обновление документации (M-12).
